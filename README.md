## Overview

This repository contains the course project for **CSC2630: Foundations of Robot Motion** at the University of Toronto. The project implements and empirically compares three asymptotically-optimal sampling-based path planning algorithms:

- **FMT\*** (Fast Marching Trees) — a fixed-sample, lazy collision-check planner that performs forward dynamic programming on a pre-sampled node set
- **BIT\*** (Batch Informed Trees) — an anytime planner that iteratively expands batches of samples within an informed search ellipse
- **NRRT\*** (Neural RRT\*) — an RRT\*-variant that uses a CNN-learned probability map to bias sampling toward high-likelihood path regions

Simulations are run on seven 2D occupancy-grid maps spanning distinct obstacle topologies (mazes, bug traps, forests, gap environments). Algorithms are benchmarked on path cost, execution time, success rate, and collision-check count across varying sample/batch sizes and start–goal separation factors.

**Key features:**
- Independent, self-contained implementations of FMT\*, BIT\*, and NRRT\* in Python
- A deep ResNet + ASPP CNN (NRRTCNN) trained end-to-end to produce per-pixel sampling probability maps
- A centralized JSON-based configuration system covering all algorithm hyperparameters and map definitions
- A Jupyter notebook (`results.ipynb`) with full comparison plots: solution cost vs. time, success rate vs. sample count, and collision checks vs. sample count
- 40 evaluation maps across 8 obstacle categories, plus test-phase maps

## Algorithms Implemented

### FMT\* — Fast Marching Trees
Implemented in `src/fmt/FMTPlanner.py`. The planner pre-samples `n` free-space states, constructs a KD-tree for neighbour queries, and performs a lazy forward-DP search outward from the start. The connection radius `r_n` is computed analytically from the Lebesgue measure of free space. Supports an optional Euclidean heuristic weight `hw` for informed expansion.

### BIT\* — Batch Informed Trees
Implemented in `src/bit_star/src/bitstar_planner.py`. At each outer iteration, BIT\* samples a batch of states within the current informed ellipse (bounded by the best known path cost), then processes vertex and edge queues in order of estimated total path cost. The batch size grows incrementally up to a configured maximum. Full prune-and-resample logic is included per the original algorithm.

### NRRT\* — Neural RRT\*
Implemented in `src/nrrt/src/nrrt_planner.py`. A trained CNN (`NRRTCNN`) takes the occupancy image (with start/goal encoded) and produces a per-pixel probability map. At each RRT\* iteration, samples are drawn either uniformly (with probability `alpha`) or from the learned distribution (with probability `1 - alpha`). Includes RRT\*-style `choose_parent` and `rewire` steps.

**NRRTCNN Architecture** (`src/nrrt/src/cnn/nrrt_cnn.py`):
- Dual-branch ResNet encoder: low-level feature map (stride-8) and high-level feature map (stride-32)
- Atrous Spatial Pyramid Pooling (ASPP) on the high-level branch with dilation rates 2, 4, 8, 12
- Robot attribute injection (clearance, step size) at both resolution levels
- Three transposed-convolution decoder blocks upsampling back to input resolution
- Sigmoid output head producing a [0, 1] sampling probability per pixel
- Trained with BCE loss, Adam optimizer (lr=1e-4), 50 epochs, batch size 10

Training data labels are generated by running A\* between random start–goal pairs on each map and accumulating the traversed pixels into a binary heatmap (`src/nrrt/src/cnn/generate_data.py`).


No additional build steps are required. All planners are pure Python.

## Configuration

All three algorithms share a common configuration schema. The master config is generated by `src/gen_config.py` and written to `src/config/config.json`.

### Generating the config

```bash
cd src
python gen_config.py
```

This reads map images from `Maps/evaluation_data/`, samples start–goal pairs at two separation factors (0.5× and 0.75× of the map diagonal), and writes all hyperparameters to `config/config.json`.

### Config schema (`src/input_json_format.json`)

```json
{
  "max_num_steps": 2000,
  "fmt": {
    "path_res": 0.1,
    "col_dst": 1.0,
    "batch_size": [5, 10, 20, 40, 80, 100, 300, 600, 1000]
  },
  "bit": {
    "max_div": 50,
    "col_dst": 1.0
  },
  "nrrt": {
    "max_div": 200,
    "col_dst": 1.0,
    "batch_size": [5, 10, 20, 40, 80, 100, 300, 600, 1000],
    "steering_radius": 10
  },
  "maps": {
    "map0": {
      "path": "/path/to/map.png",
      "s0": { "start": [x0, y0], "target": [x1, y1] },
      "s1": { "start": [x2, y2], "target": [x3, y3] }
    }
  }
}
```

**Key parameters:**

| Parameter | Description |
|---|---|
| `max_num_steps` | Maximum iterations per planning run |
| `fmt.path_res` | Step size for FMT\* collision interpolation |
| `fmt.batch_size` | List of sample counts to sweep over |
| `bit.max_div` | Number of interpolation steps for BIT\* collision check |
| `nrrt.steering_radius` | Maximum steering distance for RRT\* tree extension |
| `separation_factor` | Minimum start–goal Euclidean distance as a fraction of map diagonal |

## Usage

### FMT\*

```bash
cd src/fmt
python main.py
```

The FMT\* planner is invoked programmatically via `FMTPlanner`:

```python
from FMTPlanner import FMTPlanner
import numpy as np
from utils import load_image

world = load_image("../../Maps/evaluation_data/map_24_maze.png")
planner = FMTPlanner(world, n_samples=500, col_dst=5.0, pr=0.1, seed=42)
result = planner.plan(
    start=np.array([50, 50]),
    target=np.array([400, 400]),
    map_idx=24,
    pidx=0,
    sidx=0,
    mode='test',
    hw=0.0       # set hw=1.0 to enable Euclidean heuristic
)
print(f"Path found: {result['path_found']}")
print(f"Cost: {result['cost']}")
print(f"Execution time (ms): {result['total_execution_time']}")
```

### BIT\*

```bash
cd src/bit_star/src
python main.py config/config.json false ../results/images/
```

Arguments:
1. Path to a JSON config file (see schema above)
2. `true`/`false` — whether to display the live planning window
3. (Optional) Output directory for path images

### NRRT\*

**Step 1 — Generate training labels:**
```bash
cd src/nrrt/src/cnn
python generate_data.py
```

**Step 2 — Train the CNN:**
```bash
python train.py
```
The script trains for 50 epochs and saves checkpoints every 10 epochs to `model/model_NNN_EEE.pth`.

**Step 3 — Run planning:**
```bash
cd src/nrrt/src
python nrrt_planner.py
```

Ensure `MODEL_PATH` in `nrrt_planner.py` points to a valid checkpoint (default: `../model/model_007_050.pth`).

### Running all experiments and generating plots

```bash
cd src
jupyter notebook results.ipynb
```

The notebook reads CSV result files from `fmt/output/evaluation/`, `bit_star/results/evaluation_data/`, and `nrrt/results/`, and generates the following plot types for each of the 7 evaluation maps:
- Solution cost vs. execution time (with 95% CI bands)
- Success rate vs. execution time
- Success rate vs. sample count
- Log collision checks vs. sample count

## Results

Key empirical findings from the comparative study:

- **FMT\*** achieves competitive path costs but requires the full sample set to be pre-committed before planning begins; enabling the Euclidean heuristic weight (`hw=1.0`) yields marginal improvement in most environments.
- **BIT\*** converges to lower path costs over time in anytime fashion; its collision-check count per sample is significantly higher than FMT\* due to repeated edge-queue processing, but the gap narrows as batch size increases.
- **NRRT\*** demonstrates faster initial path discovery on maps with narrow passages (e.g., maze, bug trap) by concentrating samples in high-probability regions predicted by the CNN, but requires a pretrained model and GPU inference.
- On Maze-24 with an unreachable goal configuration, per-sample execution time was approximately 0.082s for FMT\* vs. 0.021s for BIT\* vs. 0.026s for NRRT\*.

Result plots (PNG) are saved to `src/results/` after running the notebook.
